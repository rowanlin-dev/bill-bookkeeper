# bill-bookkeeper 演示脚本

> 用途：项目演示 / 录屏 / 答辩展示。配套数据全部为**虚构、脱敏、通用化**的示例，不含任何真实个人财务信息。

---

## 0. 演示数据说明（重要）

- 数据文件：`demo/demo-data.json`（由 `demo/generate-demo.mjs` 脚本生成，可重跑）。
- 主角：虚构用户「小账」，覆盖学生/自由职业者常见收支。
- **演示数据请勿用于真实记账**。若不小心导入到自己的账本，用「重置所有数据」一键清空即可（见步骤 4）。
- 数据覆盖的场景：

  | 场景 | 在演示数据中的体现 |
  |------|------------------|
  | 收入 | 工资、兼职、奖学金、父母资助、亲友红包、存款利息、退款 |
  | 支出 | 房租、餐饮、交通、通讯、购物、医疗、娱乐、水电煤、会员 |
  | 转账 | 银行卡→微信 生活费、微信→岭南通 充值交通卡 |
  | 预计 | 月底房租/话费/会员、下月工资的「预计」条目（已确认 `已到账`，计入统计） |
  | 待生效 | 数码分期 2/3、3/3（`待生效`，不计入当前余额，演示「计划待确认」） |
  | 已取消 | 一笔「冲动购物(已取消)」（演示「取消不计入」） |
  | 固定支出 | 房租(月付)、话费(月付)、视频会员(月付)、意外险(年付) |
  | 水电读数 | 电/水各 3 期，首期 `usage/cost` 为空（演示「首期仅读数无费用」） |
  | 负债 | 信用卡、消费分期、借朋友、装修贷 |

## 1. 演示前准备

```bash
# 后端（终端 1）
cd packages/server
npm install
npm run dev          # 默认 http://localhost:3000

# 前端（终端 2）
cd packages/frontend
npm install
npm run dev          # Vite 默认 http://localhost:5173，由 vite proxy 转发 /api 到后端
```

打开前端地址，确认能正常进入主界面。

---

## 2. 一键加载演示数据（推荐开场）

1. 进入 **设置 → 🎬 演示数据** 卡片。
2. 点击 **「🎬 加载演示数据」**。
3. 弹窗确认后，系统会：
   - 先 `POST /api/data/reset` 清空当前数据、恢复 5 个默认账户；
   - 再 `GET /api/data/demo` 拉取演示账本并 `POST /api/import` 导入；
   - 自动刷新所有页面。
4. 出现「✅ 演示数据已加载」提示即成功。

> 此流程保证每次演示都从**干净状态**开始，避免上次残留数据干扰。

---

## 3. 分页面展示（按观众兴趣选讲）

| 页面 | 看点 |
|------|------|
| 仪表盘 | 总额、各账户余额（微信 2584 / 银行卡 19403 / 现金 290 / 支付宝 32 / 岭南通 15）、本月收支、现金流预测 |
| 流水 | 按账户/类型筛选；观察「已取消」条目置灰不计入；「预计」条目标记 |
| 固定支出 | 月付/年付循环提醒；与流水中的房租/话费联动 |
| 水电 | 电/水读数趋势；首期无费用、后续自动算用量与金额 |
| 负债 | 信用卡/分期/借款/贷款，含利率与到期日 |

---

## 4. 误导入后的清理（一键重置）

若演示数据被误导入到真实账本（或想回到初始状态）：

1. 设置 → 🎬 演示数据 → **「🗑️ 重置所有数据」**（危险操作区）。
2. 连续两次确认。
3. 系统清空 5 张表、id 归零，并恢复 5 个默认空账户。

> 重置**只动业务数据，不碰 `.env`、不删表结构**，可反复操作。

---

## 5. 复现 / 修改演示数据

```bash
# 调整 demo/generate-demo.mjs 后重新生成
node demo/generate-demo.mjs
# 控制台会打印各账户演示余额自检（对齐 app 真实余额口径）
```

自检口径与 `packages/server/src/services/accountBalances.js` 一致：
`余额 = 锚点 + 净流(收入−支出) + 转入 − 转出`，且 `已取消` 不计、`待生效` 不计、`预计` 仅 `已到账` 计。
